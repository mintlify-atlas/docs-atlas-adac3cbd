DTDD (Design-Test-Driven Development) is a methodology and installable Claude Code plugin that makes design documentation **load-bearing** for AI coding agents. Instead of assembling context per prompt and watching it rot, DTDD maintains a single living truth — one `DESIGN.md` per component, kept in sync with the code by a stamp-gated pre-commit hook and an independent reviewer that runs in fresh context before every commit.

## How DTDD Works

DTDD enforces a simple discipline at three tiers: design first, tests from the design, code last — and a commit gate that blocks until an independent reviewer certifies the docs match the code.

<Steps>
  <Step title="Install the plugin">
    Add DTDD to Claude Code from the marketplace, then scaffold it into your repo with one command.
    ```bash
    /plugin marketplace add ssdhage/dtdd
    /plugin install dtdd
    /dtdd-init
    ```
  </Step>
  <Step title="Run a change">
    Give DTDD a goal. It reads design docs, plans a change, executes it component by component, and brings you only the commit gate.
    ```bash
    /dtdd add retry logic to the payments worker
    ```
  </Step>
  <Step title="Drive a full spec">
    For multi-stage work, use `/dtdd-goal`. It decomposes a spec into stages, drives `/dtdd` per stage, and surfaces only commit gates to you.
    ```bash
    /dtdd-goal order cancellation — cancel from the page; payments must never charge a cancelled order
    ```
  </Step>
  <Step title="Commit with confidence">
    The design-sync agent reviews staged code against every affected `DESIGN.md` in a fresh context, stamps the commit, and the gate lets it through. You approve; the docs are always true.
  </Step>
</Steps>
